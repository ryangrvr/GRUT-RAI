OPEN PASSES -- the adjudications this program is waiting on.

WHY THIS FILE EXISTS. Every declared expected-red in expected_red.py asserts that an adjudication
is OPEN. Nothing verified that assertion. The failure it permitted: a pass closes, the test keeps
failing for an unrelated reason, and the runner prints green while citing an adjudication that no
longer exists. Staleness cannot catch it -- stale fires only when a test starts PASSING.

So the passes are named here, each declaration cites one by id, and A DECLARATION CITING A CLOSED
OR UNKNOWN PASS FAILS IN ITS OWN RIGHT. Closing a pass is a HUMAN ACT: set STATUS to CLOSED, with
the date and the ruling, and every declaration resting on it must then be removed. If the test
still fails afterwards, it is a NEW RED and says so.

THREE STATUSES, because "the symptom went away" is not "the question was answered":
  OPEN    the adjudication is live.
  CLOSED  RULED. The owner decided it; the ruling is recorded in the stanza.
  MOOT    the question DISSOLVED without being answered -- the structure it was about no longer
          exists. A moot pass is not a ruling and must never be cited as one.

AND A PASS MAY OUTLIVE ITS SYMPTOM. An OPEN pass with no failing test is normally an error: either
it was ruled and this file was not updated, or its symptom disappeared without anyone ruling. So
the runner FAILS on an open pass that nothing cites -- UNLESS the stanza declares
`MAY_HAVE_NO_SYMPTOM: yes` with the reason no instrument can see it. Those are printed as STANDING
OPEN QUESTIONS on every run, so that a quiet suite cannot become an answer by default.

Machine-read fields: `PASS <id>`, `STATUS: OPEN|CLOSED|MOOT`, `MAY_HAVE_NO_SYMPTOM: yes`. The
prose is for the reader.
