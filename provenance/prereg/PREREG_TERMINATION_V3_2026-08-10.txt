================================ THE UNIVERSAL RULES ================================

U1. STILL-OPEN IS A FIRST-CLASS OUTCOME OF EVERY CHANNEL, by construction, and every
    channel's list below actually contains it.

U2. NO MECHANICAL ACTION FIRES ACROSS CHANNELS OR ACROSS PREDICATES. A trigger executes only
    on ITS OWN banked predicate, quoted by node name and field; an answer that bears on a
    different node's trigger, or a data result that bears on a node whose own falsifier is a
    different kind of predicate, OPENS A RECORDED ADJUDICATION, never an execution.

U3. NO THRESHOLD BY GESTURE. An outcome that needs a data-grade threshold may fire only if
    the threshold is FROZEN BY NAME in a separate instrument BEFORE the data are read; if no
    such freeze exists when the data land, the thresholded outcome CANNOT fire and the
    channel reports its no-verdict or still-open line.

U4. CHERRY-PICKING FORBIDDEN: the channels below are ALL of the program's live empirical
    fronts as of sealing -- including, in v3, the second Part-7 calc's front (C5), whose
    absence from v2 made this rule's completeness claim false. The deposit reports every
    channel, each in EXACTLY ONE of its own pre-registered outcomes. HONESTY LIMIT, stated:
    this completeness claim has NO machine check (exactly the defect class that added C5);
    it is re-audited at deposit against the register's open fronts, and a front found missing
    then is reported IN THE DEPOSIT as a U4 breach, never silently appended.

U5. NO CITATION BY GESTURE: any assertion in this file about what a register field says
    carries the node id, the field name, and a verbatim quote, and is verified both ways
    (whitespace-normalized only) by the standing citation check
    (provenance/test_register_citations.py), whose coverage list includes every register
    quote below. Statements grounded in NON-register instruments (the A8 amendment record,
    the frozen gate record) are pinned by file path and record identity instead, with any
    ambiguity between candidate records resolved in-file.

U6. FORECLOSURE-BY-INACTION IS STATED, AND INSTRUMENT DUTIES HAVE DEADLINES. Every
    owner-created instrument this file depends on -- the dispatch send, the reminder, the C2
    crossing threshold, the C3 reach threshold, the activation-scale pursuit -- carries a
    CREATE-OR-DECLINE-WITH-STATEMENT duty: before the relevant data are read or the stop
    fires (whichever is earlier), the owner either creates the instrument or logs a dated
    decline with its reason in the companion event file. A channel outcome that is
    unreachable because such an instrument does not exist is reported WITH THE FORECLOSURE
    AND ITS CAUSE NAMED in that channel's own deposit line -- a (b) report is never silent
    about a foreclosed (a). CONSUMPTION IS A DUTY AND IT IS SYMMETRIC: every external result
    that has LANDED before the deposit is written is consumed against the frozen instruments
    before writing it, favorable and adverse alike; "released but not yet consumed" is
    reportable only for releases landing inside the deposit-writing window itself, with the
    gap stated. THE DEPOSIT DEADLINE: the deposit is owed within ONE CALENDAR MONTH of the
    stop.
